# Integration audit: after repairs

**18 November 2026 UTC · `arena/df553320-alolabs-ai` · release decision: ready for staging review, not approved for production.**

The repaired working tree builds from scratch. An operator can sign in, discard a settings edit, save another edit, and read the saved value back. A client lands in the portal instead of the internal dashboard. The queue, notifications, password recovery and staged backup restore were exercised with disposable accounts and data. The final local suite had **2,036 passed, 0 failed, 15 skipped**. All 15 skips require MySQL. The principal remaining gate is starting a **MySQL-generated** standalone on the exact release candidate and verifying it against a real MySQL service.

This is a working-tree result on base `4def42076c6e829cb5731f9f234be0e119fbff9c`, not a green CI run on a new commit. Nothing was committed, pushed, merged or deployed, and no production database was accessed. The [before-report](01-before.md) and its inventories are unchanged; its SHA-256 is `42d56720c37d063d5d0d55e021e45a3d9d5fd3f0a0528ea293d8c0ab988cda60`.

## Production handoff: what must happen next

1. **Candidate-SHA CI and MySQL — release gate.** On a reviewed candidate commit, run quality checks and [the MySQL workflow](../../../.github/workflows/mysql.yml). Require a real MySQL-generated Prisma client, the compatibility suite with **no skips**, and production standalone readiness reporting MySQL after a real query. The workflow now checks this on a disposable service; it was **not executed for this working tree**. Base-commit CI in the before-report is not substitute evidence. Exercise transactional claim/reclaim and reset contention on InnoDB under representative concurrency.
2. **Staging host and recovery — release gate.** Build an image/artifact for the chosen production topology. Verify loopback listener and process owner, persistent volumes and grants, Redis and object storage, one public gateway with real DNS/certificates, both socket paths, metrics and alert delivery. Restore a verified encrypted off-host backup into a *separate* database/storage namespace and reconcile rows/files before any cutover. Code rollback is not data rollback. See the [operations runbook](../../PRODUCTION-OPERATIONS.md).
3. **External workflows — enable only after acceptance.** Test recovery in a browser using a controlled address on the real mail domain, actual IMAP/TLS, and a consented OAuth exchange/refresh/disconnect. Check tenant roles with representative accounts and rotate legacy credentials. Only enable intended AI providers after a budgeted smoke run. Measure queue latency, pool use and memory on a representative workload before making capacity or availability claims.
