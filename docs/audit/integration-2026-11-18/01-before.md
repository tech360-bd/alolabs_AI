## Confirmed discrepancies and integration decisions

1. **Database lifetime & monitoring.** `src/lib/db.ts` creates a client lazily but only caches it outside production; successive property reads can allocate a new pool each time. Static control-flow finding, not a measured rate of memory growth. Readiness returns internal driver details on failure. Metrics exporter emits conflicting TYPE lines, seconds in a milliseconds field; both Prometheus configs lack auth for the protected exporter. Base scrapes the wrong endpoint; standalone also tries to scrape DB/Redis protocol ports as HTTP.
2. **Production policy vs packaging.** Both main Compose surfaces set `NODE_ENV=production` and `DATABASE_URL=file:...`; the server explicitly refuses SQLite. Dockerfile generates the default SQLite client even for the MySQL inference stack, whose app probe calls `wget` absent from the runner contract. `docker-compose.prod.yml` suggests `npx prisma db push` in a runner without Prisma CLI. `.dockerignore` lets historical bundles into the build context. MinIO credential names differ between the app and prod MinIO overrides. Raw `.sql` scripts are operator-reviewed, **not** Prisma migrations; deployment's glob does not see them. No automatic migration of production data should be introduced.
3. **Distribution/data handling.** `download/` contains 366 regular-file tar members (105 identical/243 different/18 archive-only) and 612 ZIP members (225/377/10). ZIP contains `.env` and `db/custom.db`. Values and rows were not printed; treat as potentially sensitive and review historic distributions privately. Do **not** unpack either bundle over the current checkout, restore an embedded database or resurrect obsolete middleware. ZIP-only CDN/storage paths are not evidence that a validated CDN feature exists in the current app. Source of truth is the active tree; nested reference package remains same-project material, not a second production entrypoint.
4. **Deployment/process supervision.** PM2 ecosystem starts `alolabs-agentos` with Node; `deploy/scripts/deploy.sh` queries `agentos-app` and insists its executable is Bun. `deploy/scripts/validate-env.sh` insists on unused auth names, prints a DB URL, requires `.env` even with injected environment, checks stale ports. Root `dev/start` scripts pipe through tee and can mask server failure. Root `engines.node >=20.0` understates Next's minimum; dev tool minima are higher. `.zscripts` build/install assume `/home/z/my-project`; mini-build exited **0 without building anything** here. Docker workflow references missing `steps.paid`. Standalone monitoring publishes on all interfaces with a default Grafana password. Global Caddy immutable caching applies to non-static pages and the dev block accepts a caller-selected upstream port. No blanket production hardening assertion is warranted.
5. **Admin actions and security.** 314 directly recognizable API call literals/templates compared to routes; 9 candidates, including dynamic suffixes. Four definite missing **call paths**, not four absent features: backups restore, social disconnect, worker restart, tenant user removal. Also backup create posts to schedule config, not snapshot creation. Existing restore safely stages unless an explicit in-place gate is supplied: preserve it. Worker action handler checks login, not operator role, writes global settings and simulates process restarts by recording status. Do not label this a real OS restart. Need to distinguish authorization from the presence of a guard.
6. **Packages, exports and data generation.** 14 unresolved bare-package occurrences on root-only install: 10 reference package, 2 service, 1 example, 1 explicitly optional `socket.io` helper. Some resolve only in their own installation. `test:ui` advertises a package not declared. 12 compatibility arrays in enterprise spec are intentionally empty; rerunning its generator in a copy produced a **different file** with future-phase comments. Do not populate invented employees/SOPs to pass a count. 51 Markdown relative link occurrences flagged, all inside vendored instructions, including templates/example text; do not edit signed/attributed vendor material to hide warnings. No complete remote link check, soak test or all-export proof.
7. **Merge assessment.** 0 open PRs at inspection. Of 22 remote heads, main equals HEAD and 19 others have zero commits ahead. `feat/employee-profile-completeness` has two unique commits, one empty retrigger; its `role` and `Omit<..., 'completeness'>` changes are **already in the current file**. `arena/8cc412a3-alolabs-ai` has one non-ancestor documentation change to the October deploy account; check and retain it without replacing subsequent history. No code reason to blanket-merge 131-commit-behind snapshots or push to main.

## Boundary of this audit

DB/tenant behavior on a seeded production-size MySQL instance, auth on a deployed domain, all job side effects, paid AI/telephony/mail, remote storage, encrypted off-host backups, alert delivery, Docker boot, host firewall, Ubuntu/systemd/PM2, DNS and public SSL renewal require separate runtime evidence. Platform credentials must be configured out of band. Performance/memory: pool construction risk, large Prisma declarations and large nested bundle observed; no heap profile, load SLO or concurrency certification. Logging/health/backup scripts exist; presence is not evidence of retention, monitoring or recovery in operation. Findings above prioritize safe, testable repairs; unresolved items must carry forward into the second report.
