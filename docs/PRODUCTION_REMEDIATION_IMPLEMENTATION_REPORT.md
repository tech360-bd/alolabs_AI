## Open decisions and rollout gates

- [MySQL run 44490803324](https://github.com/tech360-bd/alolabs_AI/actions/runs/44490803324) explicitly separates real compatibility and restore success from failed full schema initialization. The allowlisted server diagnostic was **“can't have a default value”**. `prisma/schema.mysql.prisma` includes `@db.LongText` fields with literal defaults (for example `Session.audience`). The exact first failing column was not established by the annotation. Do not silently substitute SQLite, remove defaults, alter schema or force Prisma past the error. DBA/schema owner: approve a compatible default-expression/schema-generation and existing-data migration plan, then verify both clean bootstrap and upgrade. The MySQL build/start gate and first login must pass before opening the PR.
- Staging owner: inventory live file paths, deploy-user permissions, control-checkout backup bundle, immutable revision transfer, log/DB privileges, Client TLS configuration, filesystem lock/rename semantics, time budget and free disk. Rehearse the full authorized deployment outside production, including boot-time PM2 resurrection. Retained releases and unverifiable legacy backups are not automatically purged.
- Security owner: configure independently verified `PRODUCTION_HOST_FINGERPRINT` under a protected main-only environment with required reviewers. Never enroll from a network scan. Approval settings are external; this branch did not change them. Privileged host automation remains a sensitive trust boundary. The scheduled backup refuses stale script hashes; rollout must not leave schedules silently failing.
- Recovery owner: prove offsite custody, encryption, object-store/ACL recovery and application-level RPO/RTO. Snapshot checksums are integrity, not authenticity or full recovery certification.
